# NAS Web App Implementation Plan

**Goal:** Implement APP-SPEC.md as a single self-hosted Rust service and React UI.
**Architecture:** axum owns the LocalNas session and retries once after authentication or transport failure. React uses only same-origin REST endpoints. A local mock is the sole verification NAS.
**Tech Stack:** axum, tower-http, Tokio, React, strict TypeScript, Vite.
**Spec:** APP-SPEC.md

## Tasks
- [x] Add serve subcommand, JSON REST API, reconnect, quota guard, static serving.
- [x] Build responsive task manager, resource picker, accessible dialogs and polling.
- [x] Add multi-stage Docker and LazyCat manifests, icon and deployment documentation.
- [x] Verify Rust build/clippy/tests, clean frontend build, and live endpoint smoke tests.

Delivery uses logical backend, frontend, packaging, tests/CI, and documentation
commits, each with the requested Assisted-by trailer. See `docs/verification.md`
for the observed checks and packaging-runtime limitation.

## Constraints And Rulings
- Existing cloud CLI remains intact; web mode uses only LocalNas and never cloud login.
- Never forward NAS tokens to the browser or bypass quota.
- LocalNas only serializes sub-file selection for file-backed requests. For selections, analyze the URL and use the returned resource file ID with CreateTaskRequest::from_file. Reject unsupported resource responses explicitly rather than silently downloading all files.
- No extra login layer is specified. Deployment must use trusted LAN or LazyCat authentication, not expose the port publicly.
- Design: cool neutral surfaces, blue action accent, system typography, left-aligned download rows, restrained 180ms feedback; native modal keyboard behavior.
